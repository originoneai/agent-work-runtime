# V1 功能优先实施计划

[范围合同](../contracts/awr-v1.json) 固定目标和门槛，[台账](../ledger/work-ledger.yaml) 保存每项任务的状态、依赖、交付物、验收和证据。[台账索引](../ledger/README.md) 由机器生成，不单独维护状态。

## 执行顺序

| 顺序 | 里程碑 | 任务数 | 主要结果 |
| --- | --- | ---: | --- |
| M0 | 筹备 | 3 | 公开仓库、许可证、原文基线、完整台账及开工入口 |
| M1 / P0 | 工程基础与 Source 接入 | 11 | Rust/SQLite、Manifest、YAML/Markdown/ADR、增量索引 |
| M2 / P0 | 任务图与工作查询 | 5 | Goal/Plan/Rule、依赖与 Ready、Decision/Evidence、FTS |
| M3 / P0 | 运行状态与事件 | 5 | Session、Claim、Event、Checkpoint、Artifact |
| M4 / P0 | 上下文编译 | 8 | Bootstrap、Work Context、规则/依赖/Delta、预算与完整性 |
| M5 / P0 | Compact 与恢复 | 3 | checkpoint、resume、中断状态诊断 |
| M6 / P0 | 状态推进与工作分支 | 7 | Source 提案与写回、领域动作、完成门槛、Branch |
| M7 / P1 | Agent 接入 | 4 | 八个 MCP 工具、Codex 接入、Kimi/Grok 指南、接口一致性 |
| M8 / P2 | 安全加固 | 5 | 路径、输入、秘密数据、并发、故障恢复矩阵 |
| M9 / P2 | 集中验证 | 8 | 完整回归、真实业务、跨平台、长台账/Compact/Token/延迟基准 |
| M10 / P3 | 发布 | 3 | 文档示例、二进制、校验文件及发布回执 |

V1 共 59 项，筹备 3 项另计。保留原方案推荐的 30 个 WorkItem ID，细分补充实现、加固、测试和发布任务。

依赖优先于编号。可执行项按优先级、里程碑顺序和台账顺序选择。例如 Work Context 总装必须等待规则、依赖、Delta、预算、完整性组件就绪，不能按 ID 直接跳过依赖。

## 可观察里程碑

- M2 完成后：能从真实项目来源定位目标、规则、任务、依赖及下一步。
- M4 完成后：能按任务和预算输出可追溯的最小上下文。
- M5 完成后：能验证 Session/Compact 中断接续。
- M7 完成后：功能与 Agent 接入形成可试用链路。
- M8–M10 完成且合同门槛通过后：评估并执行 V1 发布。

这是一份实施顺序，不是已经达到的状态。此前 10–15 个工作日的估计仍属初步估计，首次真实台账接入后再校准。

## 后置专项质量工作

用户已明确功能优先。安全专项、完整 regression、跨平台和压力/性能验证集中后置。各功能仍保留直接相关的编译与行为检查；Source-first、硬规则保留、版本/指纹冲突和证据真实性属于功能正确性，随对应功能实现。

## 待对应任务收敛的实现细节

- P0：Rust 工具链、最小版本与 crate 公共接口。
- P1：首个真实 YAML schema、Markdown 显式规则元数据与未知值策略。
- P4：token 估计器及实测 tokenizer，硬上下文超预算的错误契约。
- P6：文件落盘与数据库重索引间中断的可恢复协议。
- P7：main 最新状态与工作分支增量的优先级、worktree 边界。
- P8：实际客户端支持的生命周期能力，不预设自动 hook 存在。
- M9：脱敏真实项目、平台运行环境、独立复核者。

这些细节在指定任务实现前记录决定；不阻止工程骨架开工。

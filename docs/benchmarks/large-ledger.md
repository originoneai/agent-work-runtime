# 真实大型台账基准

AWR-P9-001 使用一个现有真实复杂项目，验证按任务读取、增量索引、无关历史隔离和投影重建。已冻结明确 Git 版本的本地快照，最终实际运行通过全部 9 项合同检查，共 16 次 CLI 调用。公开[运行报告](../../ledger/evidence/AWR-P9-001/benchmark.json)绑定代码、二进制和私有回执指纹。

[机器合同](../../tests/long-ledger/contract.json)保留方案第 52 节的最低工作数量：30 个当前任务与 100 个历史任务。按现有 AWR 状态语义划分，`planned/ready/claimed/in_progress/blocked` 为当前任务，`completed/cancelled` 为历史任务；不推测未知状态。同一个工作键只计一次，不能用同一任务的多个 Git 版本补足数量。数百 KB 的描述按至少 200 KiB 原始台账执行，不用生成文本或重复内容填充。

准入命令只读取来源、核对结构与数量并生成本地报告：

```sh
.venv/bin/python tests/long-ledger/inspect_sample.py --ledger /path/to/work-ledger.yaml --output .local/large-ledger/admission-v1.json
```

结果中的 `scale_eligible` 仅代表结构和规模适合进入下一步，`benchmark_completed` 始终为 false。真实来源、多里程碑和决策、证据与测试历史的业务含义仍须核实；不能通过一个布尔声明证明数据来自真实项目。未知字段或不兼容的来源结构须明确处理，不把不认识的任务偷偷丢弃后宣布通过。

已选样本的两份 Markdown 台账包含 150 个互不重复的任务键，其中 39 个未完成、111 个已完成，原文共 385111 bytes；加上四份支撑文档，冻结原文共 862715 bytes。六份原件均与该版本的 Git blob 逐字节一致，读取和复制后原项目保持不变。该版本是 2026-07-30 的真实本地快照，不代表原项目后续分支或最新部署状态。公开[样本盘点](../../ledger/evidence/AWR-P9-001/sample-intake.json)只保留汇总与指纹，原文、工作键、Session 内容和本地路径留在 `.local`。

上述盘点没有通过 `inspect_sample.py` 把 Markdown 当成规范 YAML。`prepare.py` 根据经过阅读和核对的私有映射，验证每行身份、原文指纹、状态图例、字段来源和不重叠的历史片段，再生成现有 YAML/规则/决策适配器可以读取的独立副本。这是本基准的准备工具，不代表 AWR 已提供通用 Markdown 台账写回适配器。

当前映射保留 150 个任务、55 段各自关联任务的历史收据、72 条证据引用（63 个不同位置）、6 个真实阶段与 3 项决策；规范台账为 249449 bytes，规模来自实际文本。未勾选但已有外部阻塞的条目显式映射为 blocked，原勾选状态与解释仍保留。当前任务与总目标的关系、已接受决策的适用范围均有显式原文依据。历史证据只作为来源引用，不冒充本次重新验证；目标架构决策保留 proposed。原文的复合阶段标签和未提取的依赖、下一步明确留有缺口，不据此宣称所有任务已可执行。

首次实际索引因历史配置或赋值文本被既有敏感内容策略拒绝。现对两段历史收据中的 6 行做显式脱敏，每行绑定原件位置和 SHA-256，副本使用 `[withheld]`；任务的验收、依赖、下一步和阻塞事实不作脱敏或删减。冻结原件与首轮失败回执继续留在本地，AWR 的敏感内容策略保持生效。

准备与运行命令使用新的本地输出目录：

```sh
.venv/bin/python tests/long-ledger/prepare.py --intake .local/sample-intake --mapping .local/mapping-spec.json --output .local/large-ledger/prepared-v1
.venv/bin/python tests/long-ledger/verify.py --awr target/debug/awr --prepared .local/large-ledger/prepared-v1 --output .local/large-ledger/run-v1
```

提交基准输入后再运行 `verify.py`；它绑定代码、二进制、原件、映射和规范源文件的指纹，实际执行单任务读取、重复索引、受控单字段更新、显式历史读取及独立项目重建。数据库查询仅用于只读核验。历史隔离探针产生的新事件会明确标成基准操作，不伪造原项目的执行历史。私有回执保存在本地，公开报告采用字段白名单并检查私有任务键、正文和路径。单元检查覆盖来源漂移、未知状态、重复身份与重复历史，不替代实际基准结果。

本样本的目标对象位于规范 YAML 台账中；编译上下文时按已映射的任务关系显式传入 `--goal`。AWR 当前的默认目标发现使用独立的 primary goal source，不会自动用 ledger 内的目标替代它。缺少目标或已接受决策的适用关系时，实际命令返回 `ContextIncomplete`；这些准备阶段失败回执保留在本地。

确认样本后，记录原件哈希和 Git 状态，制作有明确来源映射的冻结副本。所有控制性变化与重建均在可识别的新副本内执行。保留首次索引、重复索引、单任务读取、受控来源变化、当前上下文、显式历史读取和独立重建的实际回执，最后再次核对原件没有变化。原件的私有正文、人员、工作键和本地路径留在本地，公共证据仅发布经过检查的统计、范围及哈希绑定。

最终按任务读取的 CLI 标准输出为 4032 bytes，对应结构化结果的紧凑序列化为 3507 bytes；精确保留验收、阻塞、下一步和已映射的依赖事实。未变化的重索引保留身份与版本；副本内受控更新只改变一个任务的下一步和领域版本，其余事实保持一致。当前上下文排除无关已关闭任务的内容与历史探针，显式读取仍能返回完整历史。另一独立项目从相同来源重建后，各领域事实一致，未伪造会话、认领、checkpoint 或旧执行事件；两个项目的 Doctor 均无发现。六份冻结原件和原项目 Git 状态始终未变。

恢复过程由 AWR-P9-002 验证；Token/硬事实召回和延迟分别属于 AWR-P9-004、AWR-P9-005。结构准入、本地探针或样本计划都不计这些指标、E4 或发布完成。状态始终以主台账为准。

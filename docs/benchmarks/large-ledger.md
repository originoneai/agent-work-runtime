# 真实大型台账基准

AWR-P9-001 使用一个现有真实复杂项目，验证按任务读取、增量索引、无关历史隔离和投影重建。用户已提供真实项目线索，已冻结明确 Git 版本的本地快照；当前完成规模和来源盘点，尚无本项运行通过结果。

[机器合同](../../tests/long-ledger/contract.json)保留方案第 52 节的最低工作数量：30 个当前任务与 100 个历史任务。按现有 AWR 状态语义划分，`planned/ready/claimed/in_progress/blocked` 为当前任务，`completed/cancelled` 为历史任务；不推测未知状态。同一个工作键只计一次，不能用同一任务的多个 Git 版本补足数量。数百 KB 的描述按至少 200 KiB 原始台账执行，不用生成文本或重复内容填充。

准入命令只读取来源、核对结构与数量并生成本地报告：

```sh
.venv/bin/python tests/long-ledger/inspect_sample.py --ledger /path/to/work-ledger.yaml --output .local/large-ledger/admission-v1.json
```

结果中的 `scale_eligible` 仅代表结构和规模适合进入下一步，`benchmark_completed` 始终为 false。真实来源、多里程碑和决策、证据与测试历史的业务含义仍须核实；不能通过一个布尔声明证明数据来自真实项目。未知字段或不兼容的来源结构须明确处理，不把不认识的任务偷偷丢弃后宣布通过。

已选样本的两份 Markdown 台账包含 150 个互不重复的任务键，其中 39 个未完成、111 个已完成，原文共 385111 bytes；加上四份支撑文档，冻结原文共 862715 bytes。六份原件均与该版本的 Git blob 逐字节一致，读取和复制后原项目保持不变。该版本是 2026-07-30 的真实本地快照，不代表原项目后续分支或最新部署状态。公开[样本盘点](../../ledger/evidence/AWR-P9-001/sample-intake.json)只保留汇总与指纹，原文、工作键、Session 内容和本地路径留在 `.local`。

上述盘点没有通过 `inspect_sample.py` 把 Markdown 当成规范 YAML。下一步需要显式来源映射，保留原行号、内容指纹、状态图例及条目正文中的例外：有的未勾选项已部分实现但仍缺外部证据，不能据勾选框推断它已可执行。随后才能以新的可变副本执行基准，冻结原件继续保持不变。

确认样本后，记录原件哈希和 Git 状态，制作有明确来源映射的冻结副本。所有控制性变化与重建均在可识别的新副本内执行。保留首次索引、重复索引、单任务读取、受控来源变化、当前上下文、显式历史读取和独立重建的实际回执，最后再次核对原件没有变化。原件的私有正文、人员、工作键和本地路径留在本地，公共证据仅发布经过检查的统计、范围及哈希绑定。

恢复过程由 AWR-P9-002 验证；Token/硬事实召回和延迟分别属于 AWR-P9-004、AWR-P9-005。结构准入、本地探针或样本计划都不计这些指标、E4 或发布完成。状态始终以主台账为准。

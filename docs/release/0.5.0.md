# AWR 0.5.0

[简体中文](0.5.0.zh-CN.md)

AWR 0.5.0 makes daily work easier to navigate and gives agents more precise,
bounded continuity guidance. It includes PRs #27, #28, #29, #30, #31, #33, #48 and
#53. The release retains personal Workspace exchange and the existing shared HTTP
MCP runtime; the new Team implementation is outside this release.

## Changes

- **Daily navigation:** action status separates current, ready, waiting and blocked
  work. Historical verification is shown with its actual basis. `work edit` previews
  small source changes; diagnostics provide recovery steps without treating old
  completion flags as fresh evidence.
- **Focused MCP discovery:** grouped mode exposes 8 stdio tools or 9 HTTP tools,
  with bounded operation discovery. Flat compatibility mode retains 32 stdio or
  33 HTTP tools. Required context and completion checks still apply.
- **Continuity guidance:** instructions state when they apply, their evidence,
  the next action and the trigger for reassessment. Native-compaction observations
  use actual host telemetry. Keep native compaction enabled; a configurable
  post-compaction occupancy heuristic (50% by default) can advise a user-approved
  new-session handoff. Unknown usage stays unknown. This is not an infinite-context
  guarantee or a demonstrated reduction in model billing.
- **Personal Workspace exchange:** exchange files across machines through an object
  store while each machine retains its own local runtime. It does not synchronize
  live SQLite state or provide Team authorization, scheduling or semantic merging.
- **Host integration:** L0 defines the generic CLI/MCP contract, L1 gives host notes
  (including Cursor), and L2 supplies optional adapters. Cursor support is L1;
  lifecycle automation remains dependent on host capabilities.
- **Optional Inspector:** inspect projects from a local source-run interface.
  Inspector is not included in npm/PyPI packages and adds no installed launcher.
  Queries may refresh SQLite projections; explicit reindex is disabled by default.
- **Linux ARM64:** native packages now cover five platforms, including both Mac
  architectures. Both Linux packages require glibc 2.39+ (Ubuntu 24.04 baseline).

## Upgrade from 0.4.0

```sh
npm install -g @originoneai/agent-work-runtime@0.5.0
# or in a Python virtual environment
python -m pip install agent-work-runtime==0.5.0
```

1. `status` and `awr_project_status` default to the **action** view. Consumers of
   the earlier full schema must request `status --view full` or `view: "full"`.
2. MCP discovery defaults to **grouped**. Existing integrations that require the
   flat tool catalog can set `AWR_MCP_TOOL_EXPOSURE_MODE=flat` for the MCP server
   and reconnect the client so it refreshes discovery.
3. `client bind`, `progress`, `show`, `hook` and `install` require **`--client`**.
   Update scripts that previously relied on an implicit client. Consult
   `awr client <command> --help` for supported client-specific arguments.

Database schema remains **4**. Before replacing a working runtime, retain its
program, configuration, authoritative sources and consistent SQLite/runtime
snapshot. Stop writers and follow the [matched upgrade/rollback procedure](DISTRIBUTIONS.md#matched-upgrade-and-rollback-checklist).
A version label or unchanged schema alone does not prove rollback safety.

Launchers require Node 22.14+ or Python 3.9+. macOS packages require macOS 15+;
Windows is x64. See [distribution boundaries](DISTRIBUTIONS.md),
[daily work](../reference/daily-work.md), [continuity](../integrations/context-continuity.md),
[Workspace exchange](../reference/workspace-exchange.md),
[host layers](../integrations/README.md) and [Inspector](../../tools/inspector/README.md).

## Release verification

The release workflow checks the exact eight-crate source scope, versions and
publication identity, then requires native five-platform checks, Inspector tests
and npm/pip installation receipts before assembly. The assembled release contains
six npm archives, five wheels, a manifest and SHA256 checksums, bound to one source
SHA. The same verified files are used for publication.

These gates establish native and packaging behavior. They do not establish every
host's lifecycle integration, independent business acceptance, infinite context,
or end-to-end token, cost or latency improvements.

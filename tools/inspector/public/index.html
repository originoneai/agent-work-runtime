awr status

现在该干什么

AWR 把项目里的 Markdown / YAML 索引成可查询的状态。这一页是它对 「当前进行中、可以领、在等人、被卡住」四个队列的回答。

这是一个观察工具：它不编辑权威源文件，不推进工作状态，不是 agent 客户端， 也不替代 CLI 或 MCP。

— 上下文压缩率

每次编译的上下文体积

agent 每开一个新会话，都要先「读懂项目」。不用 AWR 时它得把源文件整个读一遍； 用 AWR 时它只读一个编译好的上下文包。这张图比的就是这两者的 token 数——越短越省钱、越不容易超出模型的上下文窗口。

队列

AWR 把所有工作项分进四个队列：current 有人正在做、ready 依赖都满足了可以开工、 waiting 在等一个回答或一个前置结果、blocked 真的被卡住了。 先看 blocked 和 waiting，那里才是进度停下来的地方。

    结构缺口

    这些是 AWR 在你的源文件里没找到的东西：缺目标、缺计划、缺任务结构。 agent 开不了工，原因常常不在代码，而在这里——补齐源文件，队列自己就会动起来。

      待查的运行时操作

      这些操作被中断过，结果未知——可能已经生效，也可能没有。 AWR 不替你猜，也不自动重试。先用 awr recovery inspect 查清楚再决定下一步。

        连接方式

        它不直连数据库，每做一件事都在后台跑一条 awr 命令。 所以你在界面上看到的每条命令，复制到终端里跑，结果是一样的。 你的 agent 则通过 MCP 拿同样的数据。

        $ awr-mcp --project …
        awr_project_status awr_work_ready awr_work_get awr_context_compile awr_search

        这五个是 agent 侧的只读工具，跑在一次性的内存快照上，不会改动你的项目状态。

        状态是什么意思
        
          
        
          
        
            
        
              
        fresh
        源已索引，且文件从那以后没动过。这是正常状态。
        
              
        stale
        文件改过了，但还没重新索引。这里和 agent 看到的都是旧内容，读操作可能直接返回 SourceStale。
        
              
        类型（domain）
        AWR 把源按用途分：goal 目标、plan 计划、rules 规则、ledger 工作项台账。
        
              
        角色（role）
        同一类型可以有多个源，primary 是主的那个。
        
              
        被规则挡下的源
        最常见的是疑似写了密钥。那一行可展开，能看到位置和修复建议——AWR 不会把匹配到的原值回显出来。

        术语表
        
      
    
        
    
        
      
        
        
        work item（工作项）
        
        
        一件要干的活，比如 EXAMPLE-001。它不住在某个任务系统里，就写在你项目的 Markdown / YAML 源文件中，AWR 只是把它索引出来。
        

        
        queue（队列）
        
        
        AWR 对工作项当前处境的判断：current 正在做、ready 可以开工、waiting 在等回答或前置、blocked 被卡住。它和源文件里写的 status 字段不是一回事，两者都会显示。
        

        
        context packet（上下文包）
        
        
        为某一个工作项编译出来的一段文本，装着 agent 动手前必须知道的东西：规则、验收标准、依赖、阻塞、源引文。有 token 上限。
        

        
        budget（预算）
        
        
        上下文包的 token 上限。装不下时 AWR 会省略源引文并如实告诉你省了什么，而不是悄悄截断。
        

        
        checkpoint（检查点）
        
        
        agent 干完一段活存下的存档点：消耗了什么、做到哪、下一步做什么。换会话继续干活靠它。
        

        
        open loop（未了结的事）
        
        
        悬着还没收尾的东西：一个待定的决策、一个没人 review 的改动、一个 flaky 测试。它们会被编进上下文包，免得新会话把同一个坑再踩一遍。
        

        
        drift（漂移）
        
        
        源文件改了，但还没重新索引。此时 AWR 的投影是旧的，读操作可能直接返回 SourceStale。
        

        
        revision
        
        
        项目状态的版本号。任何写操作都要先声明「我看到的是第几版」，版本对不上就拒绝——这是 AWR 防止并发踩踏的办法。
        

        
        evidence（证据）
        
        
        证明某条验收标准真的达成了的东西：一次测试运行、一份报告。完成一个工作项时，每条标准都要恰好对上一份证据。
        

        
        source of record（记录来源）
        
        
        你的 Markdown 和 YAML。AWR 的 SQLite 只是投影，随时可以重建；改内容永远是改源文件。
        

        
        刷新与只读
        
        
        这个工具不改你的 Markdown / YAML，也不推进任何工作状态。但读命令本身会刷新 AWR 的源投影（status 会报 source_refresh_performed: true），所以它不是「运行时完全只读」。重新索引是一次显式的维护操作，默认关闭。
        

        
        MCP
        
        
        agent 连接 AWR 的协议。本工具走 CLI，agent 走 MCP，两边读到的是同一份状态。
